### 1. Introduction
The overarching aim of the UGAA (Unified Geometric Attention Augmentation) project is to enhance large language‑vision models’ ability to reason about spatial relations. To evaluate progress, we built a suite of benchmarks covering various spatial‑language tasks:
- **GQA** – General Question Answering dataset with a focus on counting and relational queries.
- **POPE** – Adversarial visual‑language evaluation set that probes model consistency.
- **VSR** – Visual Spatial Reasoning benchmark (binary A/B decisions).
- **WhatsUp** – A binary spatial benchmark recently introduced.

Each benchmark required custom data loaders, image‑URL construction, and evaluation scripts. The repository evolved through a series of Git commits (see Section 6).

### 3. Dataset Preparation Pipelines
#### 3.1 GQA Filtering (CASH)
- Scripts `filter_gqa.py` and `download_gqa_subset.py` extract counting questions from the GQA validation split.
- Filtering ensures three categories (count, compare, existence) are represented for the CASH benchmark.
- Resulting JSON is cached in `datasets/cash/`.

#### 3.2 POPE Export
- `export_pope.py` reads POPE adversarial entries, attaches COCO image URLs, and writes `pope_sample_100.json`.
- Each entry includes a natural‑language question and a binary label.

#### 3.3 VSR Sample Generation
- `vsr_sample_100.py` loads the Visual‑Spatial‑Reasoning dataset, randomly selects 100 entries, and stores them as `vsr_sample_100.json`.

#### 3.4 WhatsUp Sampling
- `run_whatsapp_eval.py` (function `load_whatsup_dataset`) reads `coco_qa_two_obj.json`, samples 100 entries, constructs URLs of the form `http://images.cocodataset.org/val2017/{image_id:012d}.jpg`, and returns a list of dictionaries with `question_id`, `image_url`, `caption_a`, `caption_b`, and `correct_label`.

### 4. Model Loading & Quantisation
All evaluation scripts share a common `load_model()` implementation (see `src/run_whatsapp_eval.py`):
```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_quant_type="nf4",
    llm_int8_enable_fp32_cpu_offload=True,
)
model = LlavaForConditionalGeneration.from_pretrained(
    pretrained_model_name_or_path=MODEL_PATH,
    quantization_config=bnb_config,
    device_map="auto",
    torch_dtype=torch.float16,
    cache_dir=CACHE_DIR,
)
processor = AutoProcessor.from_pretrained(MODEL_PATH, cache_dir=CACHE_DIR)
```
- **Model Path** is configurable (`D:/models/llava-1.5-7b`).
- **Cache Directory** (`D:/models/hf_cache`) stores HuggingFace files locally.
- **CPU Off‑loading** enables running the 7 B model on consumer hardware.

### 5. Evaluation Pipelines
All scripts follow a similar high‑level flow:
1. **Load dataset** (sampled JSON). 
2. **Load model & processor** (quantised LLaVA). 
3. **Iterate** over samples → `load_image`, `build_prompt`, `run_inference`. 
4. **Parse prediction** (`parse_prediction`) into `A`/`B`. 
5. **Store results** (`save_results`). 
6. **Compute metrics** (`compute_metrics`).

#### 5.1 Prompt Construction
```python
def build_prompt(option_a, option_b):
    question = (
        "Which statement accurately describes the image?\n\n"
        f"Option A: {option_a}\n"
        f"Option B: {option_b}\n\n"
        "Answer ONLY with 'Option A' or 'Option B'."
    )
    return f"USER: <image>\n{question}\nASSISTANT:"
```
#### 5.2 Inference & Parsing
- The processor creates tensors for the prompt and image.
- `model.generate` generates a short answer (`MAX_NEW_TOKENS=10`).
- The output is decoded and the presence of "option a"/"option b" determines the label.
